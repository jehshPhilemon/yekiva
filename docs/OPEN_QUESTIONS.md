# Open questions and uncertainties

## To decide

1. **Server hosting**: HTTPS is mandatory for the Android app.
2. **Repository licence**: none for now; without a licence the code cannot be legally reused.

## To verify

1. **The UI has not been tried on a device.** The logic is tested (merge, learner, matching, WAV, tracing geometry with a fake canvas, resolution of every import) but not the real rendering nor touch gestures. First try: `node tools/serve.mjs` then `http://localhost:8080`.
2. **First CI build**: Capacitor 6 + Java 17, project generated by `cap add android`.
3. **Microphone in the Android WebView**: permission, WebM recording, decoding then conversion to 16 kHz WAV. Written to web standards, never executed.
4. **Offline voice**: is there an offline Swahili (and French) voice in the phone's speech synthesis? If not, pre-generated audio inside the packs (`say.audio` is already supported).
5. **Meta Model API**: see `API_META.md` (the `request` JSON schema, the language hint, Swahili absent from the 25 verified languages). `node tools/probe-meta.mjs` removes these doubts with a key.
6. **Performance** on an entry-level phone: animation and tracing smoothness, APK size.
7. **SAM 3.1** on real photos, and **Muse Wonder** (feature not verified).

## To build next (proposed order)

1. First try in a browser; fix what breaks.
2. First green APK build, then commit `app/android/`.
3. **Glyph authoring tool**: the real strokes of each letter (order and direction) are pedagogical content. Idea: a page where the letter is drawn and `glyphs.json` is exported; to be validated with someone who teaches handwriting.
4. Stroke validation (direction and order).
5. Real audio files in the packs.
6. Let the learner model drive the order of steps.
7. Meta wiring (transcription first, then Muse Spark), pack-building pipeline.
8. Android back button, pack download/sharing, profiles.
